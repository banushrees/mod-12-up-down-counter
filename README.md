# Mod-12 Up/Down Counter
### Project Overview

This project focuses on the design and verification of a Mod-12 Up/Down Counter using Verilog and SystemVerilog.The counter is designed to operate in both up-counting and down-counting modes and supports control operations such as reset and load.

A SystemVerilog-based verification environment is developed to generate stimulus, drive the DUT, monitor the DUT activity, calculate expected results using a reference model, and compare the expected and actual outputs using a scoreboard.The verification environment also includes constrained-random stimulus, functional coverage and cross coverage to improve verification completeness.

The Mod-12 Up/Down Counter supports the following operations:

Down-counting operation
Reset operation
Load operation
Enable/disable functionality, as implemented in the RTL
Boundary/wrap-around behavior
Verification using constrained-random stimulus

 # Verification Environment

The verification environment is developed using SystemVerilog and follows a modular testbench architecture.

The main components of the environment are:

## 1.Generator

The generator creates transactions containing different combinations of counter control signals and operations.

Constrained-random stimulus is used to generate different scenarios and improve the range of conditions exercised during verification.

## 2.Driver

The driver receives transactions from the generator and converts them into signal-level activity that is applied to the DUT through the SystemVerilog interface.

## 3.Interface

The interface provides the connection between the testbench components and the Mod-12 counter RTL.

It groups the relevant DUT signals and provides a clean communication path between the driver, monitors and DUT.

## 4.Write Monitor

The write monitor observes the relevant input and control signals applied to the DUT.

It collects the observed activity and makes it available to other verification components.

## 5.Read Monitor

The read monitor observes the counter output generated by the DUT.

It captures the actual DUT response for checking against the expected result.

## 6.Reference Model

The reference model independently calculates the expected counter output based on the applied control operations.

This expected value is then provided to the scoreboard for comparison.

## 7.Scoreboard

The scoreboard compares the expected output from the reference model with the actual output observed from the DUT.

Any mismatch between the expected and actual values is reported as a verification failure.

## 8.Functional Coverage

Functional coverage is used to determine whether important counter operations and scenarios have been exercised during simulation.

## Verification Flow

The overall verification flow is:

1.Transaction Generation → Driver → DUT → Monitor → Scoreboard
2.The reference model generates the expected output independently.
3.The scoreboard then performs:\
Expected Output ↔ Actual DUT Output
4.Functional coverage collects information about the scenarios exercised during simulation.
